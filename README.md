# RAG Jev

[简体中文](README.md) · **[English](README.en.md)**

国服《英雄联盟》版本更新公告的本地 RAG 问答，加上一个 **Jev（TypeSafe System One）决策层**。

[![tests](https://github.com/Nixz0824/rag-jev/actions/workflows/ci.yml/badge.svg)](https://github.com/Nixz0824/rag-jev/actions/workflows/ci.yml)
![python](https://img.shields.io/badge/python-3.12%2B-blue)
![license](https://img.shields.io/badge/license-MIT-green)

回答里的数字全部来自官方公告的结构化抽取结果，**不经过生成模型**。

> **能确定的交给代码；只有语义不确定时才交给 Jev。**

这不是一句口号，而是可以被测试与评测检查的链路行为：`26.17 薇恩 W 真实伤害是多少`
这类问题的版本、对象、技能、字段全部由正则与别名表确定，**语义调用为 0 次**；
只有规则没能理解的问法（「那个技能伤害」）才会让模型参与，而且模型参与的每一步
都能在页面上看到花了多少钱、有没有被采用。

---

## Jev 在 RAG 生命周期里的四个位置

```text
Query Understanding    规则解析 → 语义补全（只有规则没理解的槽位才问模型）
        ↓
Retrieval Planning     分层路由：该去哪一块知识空间找（不确定时开 2 条分支）
        ↓
Candidate Selection    候选重排：已检索出的候选里选哪一条
        ↓
Answer Verification    证据判读：渲染出的声称有没有被证据支持
```

四个角色分别对应 `routing.SemanticRouter._semantic_fallback`、
`routing.SemanticRouter._hierarchical_route`、`jev.rerank`、`jev.judge_many`；
每个角色都会在会话里留下 `called` / `bypassed` / `fallback` / `failed` 四种状态之一，
**「跳过」也是要说明原因的结果**，不是空白。

## 为什么不是"又一个 RAG demo"

| 维度 | 常见 RAG demo | 本项目 |
|---|---|---|
| 数字来源 | 让模型写数值 | 模板渲染，数值只来自公告 chunk（`_render`） |
| 模型位置 | 全流程交给 LLM | **只在需要判断的地方出现**：四个角色之外的环节全是确定性代码 |
| 版本处理 | 纯相似度检索 | **元数据过滤先于排名**；`26.17` / `16.17` / `15.13` 三套版本号自动归一 |
| 模型会不会被浪费 | 每个问题都调用 | 全确定的问题 **0 次调用**（有测试固定）；每问平均 0.86 次语义调用 |
| 不确定时怎么办 | 选一个然后收窄 | 首选与次选接近时**保留两条搜索分支**，并额外保留一条无过滤保守路径 |
| 可关闭 / 可比较 | 无 | `RAGJEV_ROUTING_MODE` = `off` / `shadow` / `active`，可跑对照实验 |
| 是否夸大自己 | 只报提升 | 分层路由 live 实测**没有提升**（off 7/8 = active 7/8），README 与报告照实写 |
| 评估 | 无，或自己写几条同源问题 | **78 题独立盲测**（出题方禁读语料）+ 48 条解析盲测 + 18 条陷阱题 + 8 条路由案例；全部用真实模型跑过 |
| 负面结论 | 不写 | 三种排序在过滤后打平、门槛测量后不采用、重排空间很小、路由没有测到收益——都留在报告里 |
| 工程 | 一个 notebook | 175 项单元测试 + GitHub Actions + 进程 Job Object + 索引指纹 + 公告原文不入库 |

## 界面

本地单页工作台（`web/`），左侧竖排索引，开场 / 问答 / 结构 / 架构 / Jev / 数据 / 对比七段。

**问答**：回答里的数字直接来自公告条目；右边同步显示**本次查询执行图**
（每个阶段真的走到了哪一步、哪些阶段被跳过、为什么）、证据列表与 Jev 决策面板。

![问答](docs/screenshots/ask.png)

**架构**：静态架构图，按数据层 / 查询理解 / 检索 / 决策 / 回答安全五层说明整条链路，
每个节点都对着代码里的文件与函数；琥珀金节点就是 Jev 会介入的位置，
一眼能看出它出现在「查什么」和「选哪条」上，而从不出现在「写什么数字」上。

![架构](docs/screenshots/arch.png)

**六段流水线**：从公告抓取到模板渲染，Jev 按需出现在四个位置。

![流水线](docs/screenshots/flow.png)

**Jev 到底加成了什么**：四个实验的图表（自检注入点图、排序能力对照、生产链路记账）。

![Jev](docs/screenshots/jev.png)

**评测与语料**：盲测成绩、扩容前后、逐版本语料结构；表格与「Jev 净贡献」清单都读 `docs/*.json`。

![数据](docs/screenshots/data.png)

支持分享链接：`/?q=26.17 薇恩 W 真实伤害是多少` 打开即提问，`/?view=jev` 直接跳到某个区块。

### 分层路由 8 例（`scripts/evaluate_routing.py`，真实模型，重复 3 次）

`active`（分支真实参与检索）。`shadow` 与 `active` 的调用次数相同，

| 口径 | 命中@1 | 命中@5 | 语义调用 | 分叉题数 |

- **结论：本版本没有测到分层路由带来的命中率提升** —— off 与 active 都是 7/8，

  但在这批题上没有转化成更好的首选。
- 唯一答不对的那条（`r05`）是**语料上不可判定**的问法：卡西奥佩娅在 26.18 的

  两种口径都答不对。这是已知限制，不是回归。
- **完全确定的问题 5/8 条零语义调用**；每问平均 **0.86** 次语义调用。
- 口径说明：以上是 **live**（真实 TypeSafe API）。此前用案例文件里手写分布跑出的

## 三、Jev 到底加成了什么（四个可复现实验）

不是"接了模型所以更强"，而是把每个作用分别测出来，含它**没有**用的地方。

### 实验 1 · 检索**之前**：分层路由有没有用

见上方「分层路由 8 例」。用真实模型重复 3 次后的结论：

- **没有测到收益**：off 与 active 都是 **7/8**，改善 0、损害 0。分叉与合并都在正常工作，
  只是在这批题上没有让首选变得更好。
- **原因不是脚本坏了**：8 条里 5 条根本不需要模型（规则已定出槽位），
  剩下 3 条里 2 条的唯一合理解读本来就能被检索命中，第 8 条在语料上无法判定。
- **代价是实打实的**：每问平均 0.86 次语义调用、约 0.5s 路由耗时。
  也就是说在一批「可判定的问法」上，这份开销没有换到命中率。

所以本版本对分层路由的定位是：**机制可用、可关闭、可对照，但没有证据表明它提高了准确率**。
要判断它是否值得，需要更多真正模糊的问法（当前案例集只有一条，且那条无解）。

### 实验 2 · 排序能力：去掉字段预过滤，同一批候选比首选

生产链路先用元数据过滤把候选压到 1—6 条，Jev 几乎没得选。所以专门做一组对照：
候选集取「该对象在该版本的全部改动行」（≥2 条才计入，共 49 条案例），同一批候选下比首选命中。

| 口径 | 首选命中 |
|---|---|
| BM25（元数据过滤后） | 47/49 |
| **Jev 重排（同一批候选）** | **48/49** |

Jev 独对 1 条、BM25 独对 0 条。命令：`python scripts/evaluate_jev.py --ranker`

### 实验 3 · 回答自检：注入错误数字，看它抓不抓得住

把已经答对的回答原样送进自检（对照组），再把渲染行里**最后一个数字改掉 1**（注入组）：

| 组 | 支持度（均值） | 判定不合格 |
|---|---|---|
| 对照（正确回答） | **0.96** | 0/24（无误报） |
| 注入（数字改错） | **0.04** | **24/24（全检出）** |

两次调用合计 $0.00045。命令：`python scripts/evaluate_selfcheck.py`

### 实验 4 · 生产链路逐条记账：Jev 到底改了几条

91 条可判定案例（两批盲测 + 同源定点）：

| 情况 | 条数 |
|---|---|
| 过滤后候选不足 2 条，Jev 无法介入 | 41 |
| Jev 改序 | **1**（改对 1、改错 0） |
| Jev 保留顺序 | 90（其中第 1 条本来就对 87、本来就错 3） |

命令：`python scripts/evaluate_jev.py`　报告：[docs/Jev效果.md](docs/Jev效果.md)

### 结论

- **值**：候选歧义或问法与标签不一致时能捞回正确行（同源定点命中@1 **21/23 → 22/23**）；
  回答自检是唯一能对「数字是否被证据支持」做判定的环节（注入检出 24/24、误报 0，
  盲测 78 题自检 **40/40**）。
- **不值**：元数据过滤已经把检索变简单，重排空间很小（91 条里只改 1 条）；
  解析层完全不需要模型；**分层路由没有测到命中率提升**（off 7/8 = active 7/8）。
- **成本**：重排约 $0.0001/次；盲测 78 题共 16 次调用、$0.00225；同源 84 例 37 次调用、$0.00362；
  分层路由每问 0.86 次调用、约 0.5s；全确定的问题 0 次。
- **降级**：没有 key 时自动跳过全部模型环节并在轨迹与阶段账本里标注，链路照常可用。

## 盲测抓到的问题（都已修复）

| # | 问题 | 怎么发现 | 修复 |
|---|---|---|---|
| 1 | 方向判定只看第一个数：`30-60% → 30-50%` 被判成「调整」而不是削弱 | 盲测聚合题「锐雯历次被削弱是哪些版本」 | 逐个数对比 + 混合取和；`adjust` 从约 700 条降到 81 条 |
| 2 | 区间连字符被当成负号：`30-60%` 解析出 `[30, -60]` | 同上 | 数字正则加前置断言，连字符不再当作符号 |
| 3 | 技能写在字段名里（`R 被动过载涌动伤害`）时技能归属丢失 | 盲测单点题「瑞兹 R 被动过载涌动伤害」 | 解析时从字段名前缀提取 Q/W/E/R |
| 4 | 短别名压过主体名：提问「瑞兹 R 被动过载涌动伤害」被解析成物品「过载」 | 同上 | 别名匹配改为「最长优先 → 位置靠前优先 → 英雄优先于装备」 |
| 5 | 俗称缺失（船长/鸟皇/熊/猴子/诺手/铁男/冰女等） | 盲测单点题「船长 Q 蓝耗」「鸟皇基础生命值」 | 英雄俗称补到 100+ 条、装备规则 74 条（含 IE/BT/QSS/PD 等英文缩写） |

## 快速开始

```powershell
# 1. 依赖：Python 3.12+ 与 numpy
python -m pip install numpy

# 2. 模型（约 1.7 GB，脚本按 SHA-256 校验）
python scripts/download_runtime.py
python scripts/download_models.py

# 3. 语料（需要联网：Data Dragon + 国服公告）
python scripts/build_aliases.py
python scripts/ingest_qq.py --count 30 --pages 90   # 想快就 --count 10

# 4. 启动（首次会构建向量索引）
python launch.py
# 浏览器打开 http://127.0.0.1:18890
```

停止：`python launch.py --stop`，或运行 `停止服务.cmd`。

### Jev（可选）

```powershell
$env:TYPESAFE_API_KEY = "sk-..."        # 或写入 runtime/jev-key.txt
$env:RAGJEV_ROUTING_MODE = "active"     # off / shadow / active，默认 active
```

没有 key 时系统照常工作：确定性解析、元数据过滤、混合检索、模板渲染全部可用，
语义补全 / 分层路由 / 重排 / 自检会被跳过，**并且每一处跳过都会写进轨迹与阶段账本**
（`/api/health` 会显示 `jev.enabled=false` 与当前 `routing_mode`）。

### 三种路由模式

| 模式 | 行为 | 用途 |
|---|---|---|
| `off` | 完全使用确定性解析，不调用任何模型做理解 | 复现 0.13.0 的基线 |
| `shadow` | 照常做语义判断并记录，但**不影响检索** | 与 active 对照：调用次数相同，差异只来自「是否使用」 |
| `active` | 分支真实参与检索与合并 | 生产默认 |

## 数据边界（请按此引用本项目）

- 主语料是**国服官方公告正文**，覆盖英雄、装备与系统数值改动；皮肤、炫彩、云顶、模式机制不在抽取范围。
- 公告里没有写的**版本内热修**不在语料中，系统会明确提示而不是猜。
- 公告只记录改动，因此「最近一次调整」**不等于**「当前实际数值」。
- 国服公告数值与其它服务器可能不同，本项目以国服为准，不做跨服务器断言。
- 解析可能漏项：`docs/解析覆盖率.md` 记录每个版本的解析量与未识别字段。
- 分层路由用真实模型重复 3 次测量，**没有测到命中率提升**（off 7/8 = active 7/8）；
  唯一答不对的题目在语料上不可判定，因此样本量不足以支撑任何「有提升」的说法；
  `docs/Jev分层路由.md` 的「没有证明什么」一节是结论的一部分。

## 版权

公告原文只保存在本地 `data/patch/`（已被 `.gitignore` 排除），仓库里只有抓取解析脚本、统计与少量测试样例。
