## 为什么扫全历史

只扫工作区会漏掉最危险的情况：密钥曾被提交、后来 `git rm` 掉。文件不在 HEAD 里，但它仍在
`git log` 可访问的历史中，推上去就等于公开。所以这次用 `git rev-list --objects --all` 取全部对象、
`git cat-file --batch` 逐个读入内存后匹配。

> 第一版审计脚本报「历史 blob 总数：3」，这对一个有 50 次提交的仓库是不可能的 —— 是我的批次解析
> 写错了、提前退出，会把一次**失败的扫描**伪装成「全部通过」。重写后确认 453 个 blob，
> 并且加了断言：blob 数少于 50 就直接以退出码 2 失败，不允许在扫描不完整的情况下报安全。
