  - 正文里的数值形如「冷却时间：4 ⇒ 3.5」（箭头是 HTML 实体，页面上显示为 ⇒ 或 →）

## 三、产出（严格按要求格式写文件）

写到：<项目根>\tests\cases\blind_cases_2.json
结构：{"note": "总题数、各 kind 数量、覆盖版本、来源（国服/英文）", "cases": [...]}
每题严格只有 id/question/kind/expect/source_url 五个键，共 40 题：

1) 单点数值题 22 题，kind = "single"
   {"id": "c01", "question": "15.20 沃利贝尔 E 法强收益率改成多少", "kind": "single",
    "expect": {"patch": "15.20", "subject": "沃利贝尔", "ability": "E", "field_key": "ability_power", "value": "70%"},
    "source_url": "https://lol.qq.com/gicp/news/410/xxxxxxxx.html"}
   - field_key 只能从这里选：damage, cooldown, cost, crit, health, health_regen, mana, armor,
     magic_resist, resistances, attack_damage, ability_power, attack_speed, movement_speed, range,
     shield, heal, price, duration, stacks, max_rank, ability_haste, cast_time, magic_pen, armor_pen,
     slow, tenacity, lifesteal, exp, speed
   - ability 可选，取值 "Q"/"W"/"E"/"R"/"被动"
   - value 是公告里那条改动**新值**的连续子串，必须能在公告页面逐字复制到

2) 改动汇总题 6 题，kind = "overview"
   {"id": "o01", "question": "15.20 有哪些英雄被削弱", "kind": "overview",
    "expect": {"patch": "15.20", "subjects_any": ["沃利贝尔", "希瓦娜"]}, "source_url": "..."}
   - subjects_any 至少 2 个正确答案（答出其一即可），用官方中文名

3) 跨版本聚合题 6 题，kind = "aggregate"
   {"id": "g01", "question": "沃利贝尔从 15.13 到 25.11 一共改了几次", "kind": "aggregate",
    "expect": {"subject": "沃利贝尔", "patches": ["15.20", "15.22", "25.11"], "mentions": "共被改动"},
    "source_url": "逐版本核对：15.20、15.22、25.11 的公告里都有沃利贝尔改动"}
   - patches 列出该区间内**确实有过改动**的版本（2–4 个即可，不必列全），系统的时间线必须覆盖它们
   - mentions 写 "共被改动"（普通聚合）或 "削弱"（带方向收窄的聚合，例如「历次被削弱的记录」）
   - 出题前必须逐版本核对公告，确认这些版本里真的有该对象的改动

4) 确实没有改动的题 3 题，kind = "absent"
   {"id": "a01", "question": "15.21 沃利贝尔改了什么", "kind": "absent",
    "expect": {"patch": "15.21", "subject": "沃利贝尔"}, "source_url": "该版本公告确认没有这个对象的任何改动"}
   - 必须先确认：该对象在该版本公告里完全没有任何改动

5) 应拒答题 3 题，kind = "out_of_scope"

    "source_url": "不属于公告数值范围"}
   - 可以问：皮肤、位置、胜率、其它服务器、不存在的版本、版本内热修、攻略出装

## 四、题目风格（很重要）

- 用玩家真实会说的问法：混入口语与俗称（压缩、发条、ez、牛头、男枪、刀妹、犽宿），允许错别字与省略。
- 约 30% 的题不写版本号（考察默认版本与追问行为）。
- 2–4 条中英混写，例如 "Volibear E AP ratio 现在多少"。
- 每题只问一件事；同一「版本 + 对象 + 字段」只能出现一次；20 个版本每个至少 1 题，15.20/25.11/26.1 这类
  大版本至少 3 题。

## 五、生成后自检（必须做，结果写进 note）

1. 每题的 value / subjects_any / patches 都能在对应 source_url 页面逐字找到；
2. 没有重复的（版本 + 对象 + 字段）；
3. note 里写清：总题数、各 kind 数量、覆盖版本列表、来源是国服还是英文；
4. 用 python -c "import json;d=json.load(open(r'<项目根>\tests\cases\blind_cases_2.json',encoding='utf-8'));print(len(d['cases']))" 验证可解析，并把题数告诉我。
