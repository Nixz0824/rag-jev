# 交接文档

> 自包含：读完这份就能继续开发。常驻约定见根目录 `AGENTS.md`。

**快照时间**：2026-09-20 · 版本 0.1.0（M0 + M1 完成）

## 1. 现状

国服《英雄联盟》版本更新公告的结构化问答：公告 → 结构化 chunk（数值改动 + 叙述）→ 版本感知检索 → 模板渲染 / 受限归纳，Jev 在候选上做重排。

- 语料：最近 10 个版本（26.9—26.18），1176 条（数值改动 500 条左右，叙述 670 段左右），86 个英雄、35 件装备出现在改动里。
- 检索：元数据过滤（版本/对象/类型/技能/模式）在打分之前；BM25 + 向量 + RRF。
- 决策：`jev.rerank` 对每条候选问一个 noul（是否正是用户问的那条），并用一个 choice 做相对选择；失败会降级并在 `session["trace"]` 留痕。
- 前端：`web/` 单页工作台（版本选择、证据列表、决策轨迹、准确性反馈）。
- 测试：59 项，无模型无网络可跑。

## 4. 数据流

```
POST /api/chat
 └─ PatchEngine.chat
    ├─ parse：版本归一（26.17 / 16.17 / 16.17.1）→ 对象（别名表）→ 技能 → 字段 → 模式
    ├─ 边界：不在覆盖范围 / 超范围主题 / 无对象 → abstained 或 clarifying（带其它版本提示）
    ├─ Retriever.search(where=…)     # 元数据先过滤
    ├─ jев.rerank(hits[:20])         # noul 逐条 + choice 相对选择；失败降级并记 trace
    └─ 渲染：数值来自 chunk；模板句在 _render
```

## 5. 不变量

1. 数字只来自语料，`_render` 不接受模型输出。
2. 解析与措辞只在 `patch_schema.py` 定义，脚本与引擎共用。
3. 元数据过滤先于排名。
4. Jev 失败必须留痕，不能静默降级。
5. 公告原文不进仓库（`data/patch/raw/`、`knowledge.json`、`index.*` 已忽略）。
6. 新增行为必须带测试。

## 6. 已知限制

- 解析覆盖率不是 100%：26.10 有 17 条字段未归一到固定键（多为系统/符文条目），26.16 有 10 条技能字段无技能归属；这些行仍以原文保留，但不会被字段过滤命中。
- 叙述行（约占 57%）只用于检索与「同一对象的其他改动」展示，不参与数值回答。
- 26.9 的「任务进度/任务奖励」一类系统条目字段名很长，渲染时以原文标签呈现。
- 未做：英文公告对照核验、检索 A/B 指标、盲测集、版本对比视图。
- 门槛常量 `GATE_SIMILARITY=0.48` / `GATE_BM25=6.0` 是从旧语料继承的**未校准值**，仅用于 `/api/health` 展示；当前主链路不依赖它（回答路径由元数据过滤 + 结果非空决定）。校准前不要把它写进报告。
