# 交接文档

> 自包含：读完这份就能继续开发。常驻约定见根目录 `AGENTS.md`。

**快照时间**：2026-09-29 · 版本 0.14.0（Jev 分层路由完成）

## 1. 现状

国服《英雄联盟》版本更新公告的本地问答：公告 → 结构化 chunk → **查询计划** →
分层语义路由（可选）→ 元数据过滤 + BM25/向量/RRF → Jev 重排 → 模板渲染 → Jev 证据判读。

一句话架构：**能确定的交给代码，只有语义不确定时才交给 Jev。**

- 语料：30 个版本（15.13—26.18），4995 条（结构化数值改动 2212 条、公告叙述 2783 段），
  170 个英雄、85 件装备出现在改动里；统计见 `docs/语料统计.md`。
- 检索：元数据过滤（版本/对象/类型/技能/模式/**字段族**）在打分之前；BM25 + 向量 + RRF。
- 查询理解：确定性解析（正则/别名/技能名/字段规则）先跑完并**关闭**它能确定的槽位；
  只有剩下的未决槽位才会交给 Jev（`routing.SemanticRouter`）。
- 决策：Jev 四个角色 —— 语义补全 / 分层路由 / 候选重排 / 证据判读；
  每次调用的成本与延迟都记在 `session["jev_phases"]`，跳过也记录原因。
- 前端：`web/` 单页工作台（版本选择、证据、轨迹、**架构图**、**逐查询执行图**、Jev 决策面板）。
- 测试：196 项，无模型无网络可跑。

## 4. 数据流

```
POST /api/chat
 └─ PatchEngine.chat
    ├─ guard（问候/越权/超范围/其它服务器/位置）        ← 全确定性，先于任何模型调用
    ├─ PatchEngine.plan(text) → QueryPlan
    │    ├─ patches：正则 → canonical_patch（26.17 / 16.17 / 25.15 三轨归一）
    │    ├─ subject：别名表最长优先 → 找不到则词形候选（difflib，≤3 个）
    │    ├─ ability：显式字母 → 大招 → 被动 → 技能名
    │    ├─ field_keys：patch_schema.FIELDS 规则；命中不了但有数值意图则标 ambiguous
    │    ├─ mode / type / intent：能确定才确定
    │    └─ 每个槽位记 Slot(value, source, status, confidence, why, candidates)
    ├─ routing.SemanticRouter.plan(plan, shortlist)     ← RAGJEV_ROUTING_MODE 控制
    │    ├─ 只对未决槽位提问；已 closed 的槽位不进提问集合
    │    ├─ 语义补全：一次 classify_many 批量问所有未决槽位
    │    ├─ 分层路由：字段二级（族 → 键）、低置信槽位展开为竞争分支
    │    └─ 产出 route_paths（1 条读法 + 可选竞争读法 + 1 条无过滤保守路径）
    ├─ PatchEngine._branch_search：逐分支 metadata filter + BM25/向量/RRF
    │    └─ routing.merge_candidates：按 score_branch/(60+rank) 加权 RRF 融合
    ├─ jev.rerank(hits[:20])                            ← noul 逐条 + choice
    ├─ _render：数值只来自 chunk
    └─ jev.judge_many(渲染行, 语料句 + 结构化数值) → 支持度 < 0.5 时加提示
```

## 5. 不变量

1. 数字只来自语料，`_render` 不接受模型输出。
2. 解析与措辞只在 `patch_schema.py` 定义，脚本与引擎共用。
3. **确定性已确定的槽位对模型关闭**：`QueryPlan.resolved_deterministically` /
   `Slot.closed`。新增语义调用前必须先证明该槽位真的未决。
4. 元数据过滤先于排名。
5. Jev 失败或跳过必须留痕：`session["trace"]` + `session["jev_phases"]`，不能静默。
6. 语义误判不能让正确行不可达：任何收窄都会附一条无过滤保守路径。
7. 公告原文不进仓库（`data/patch/raw/`、`knowledge.json`、`index.*` 已忽略）。
8. 新增行为必须带测试。

## 6. Jev 的四个角色（不要混为一谈）

| 角色 | 解决什么 | 代码 | 典型状态 |
|---|---|---|---|
| A 语义补全 | 规则没理解的问法 | `router._semantic_fallback` | 槽位确定时不调用（bypassed） |
| B 分层路由 | 该去哪一块知识空间找 | `router._hierarchical_route` | 首选明显领先时单路径 |
| C 候选重排 | 已检索出的候选里选哪条 | `jev.rerank` + `MIN_RERANK_GAP` | 候选 < 2 条时 bypassed |
| D 证据判读 | 渲染出的声称有没有被证据支持 | `jev.judge_many` | 未开启自检时 bypassed |

`bypassed` 是**设计结果**，不是故障：它回答的是「什么时候不用模型」，
这一点和「什么时候用」同样重要。前端与评测都按这四种状态显示。

## 7. 已知限制

- **分层路由的收益样本量小**：`docs/Jev分层路由.md` 里能触发路由的只有少数题，
  `off 5/8 → active 8/8` 证明的是机制有效，不是收益幅度；门槛（0.35 / 0.60）
  是保守取值而非最优值。
- **fixture 口径不是模型准确率**：没有 `TYPESAFE_API_KEY` 时评测回放案例文件里
  手写的分布，只测链路行为。真实模型判断能力尚未测量。
- 解析覆盖率不是 100%：26.10 有 17 条字段未归一，26.16 有 10 条技能字段无技能归属；
  这些行仍以原文保留，但不会被字段过滤命中。
- 叙述行（约占 57%）只用于检索与「同一对象的其他改动」展示，不参与数值回答。
- `engine.GATE_SIMILARITY` / `GATE_BM25` **已测量但未采用**（范围内与越界相似度重叠，
  见 `docs/门槛校准.md`）。范围判断由关键词黑名单与「没认出对象先追问」承担。
- 元数据过滤后候选常常只有 1—6 条，Jev 重排空间很小 —— 这是 0.12.0 就留下的负面结论，
  0.14.0 没有推翻它：新增的分层路由是把 Jev 前移到检索**之前**，而不是让重排变得更重要。
- 字段族划分（`taxonomy.FIELD_FAMILIES`）是按语料分布人工归类的，不是学出来的；
  新增字段需要手工归族，`tests/test_query_plan.py` 会强制这一点。

## 8. 下一步（按性价比排序）

1. **补真实模型的 live 评测**：有 key 后跑 `python scripts/evaluate_routing.py --live`，
   把 fixture 口径换成真实分布；这是当前最大的测量缺口。
2. **扩大模糊问法案例集**：现在能触发路由的题太少，无法给出可信的收益区间；
   需要专门设计「技能/字段都没说清」的问法，而不是继续加明确问题。
3. **实体消歧**：`PatchRetriever.subject_shortlist` 目前靠 difflib + 包含关系，
   候选常为空；可以引入技能名与别名的更宽召回，再用 `jev.shortlist` 收敛。
4. **跨版本聚合也走路由**：当前 `aggregate` 分支完全确定性，若问法模糊（未写区间）
   仍可考虑让模型判断区间。
5. **反馈回收**：`python scripts/review_feedback.py` 把页面上的「有误」样本变成案例草稿。
