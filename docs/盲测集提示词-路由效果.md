# 提示词：生成「分层路由效果盲测集」

> 用途：把下面 **方框内的全部内容** 复制给 Codex（或其它出题模型），让它生成
> `tests/cases/routing_effect_cases.json`，再用
> `python scripts/evaluate_routing.py --live --repeat 3 --cases tests/cases/routing_effect_cases.json`
> 测量分层路由到底有没有提升。
>
> 出题方**必须禁止读本项目语料**（`data/patch/`、`docs/语料统计.md` 等），
> 只能读官方公告。理由见提示词内「为什么这么苛刻」。
>
> 注：下面用五重反引号包住，只是为了在本文档里正确显示——你复制时不需要连围栏一起复制。

`````text
你是一名《英雄联盟》数据出题员。请为「国服版本更新公告问答系统」出一套**中文测试问题集**，
用来测量「分层语义路由」（系统先判断问题问的是哪个技能/哪类数值，再去检索）到底有没有用。

## 一、输出要求

把结果写成一个 JSON 文件，路径**必须**是：

    tests/cases/routing_effect_cases.json

文件结构（严格遵守，字段名不得改动）：

{
  "title": "分层路由效果盲测集",
  "note": "一句话说明出题口径与禁止事项",
  "cases": [
    {
      "id": "e01",
      "kind": "routing_effect",
      "question": "26.18 卡蜜尔那个盾改成多少了",
      "expect": {
        "subject": "卡蜜尔",
        "rows": {
          "patch": "26.16",
          "subject": "卡蜜尔",
          "ability": "被动",
          "field_key": "shield",
          "value": "10 / 15 / 20 / 25%最大生命值"
        }
      },
      "why": "「那个盾」唯一指向被动护盾；该版本该英雄共 5 条改动行，不筛技能会先命中冷却行。"
    }
  ]
}

字段说明：

| 字段 | 含义 | 硬性要求 |
|---|---|---|
| `id` | 编号 | `e01` 起连续编号，不重复 |
| `kind` | 固定值 | **必须**是 `routing_effect` |
| `question` | 中文提问 | 见第三节 |
| `expect.subject` | 问题指向的对象 | 官方公告里的名字（英雄用通行中文名，装备用全名） |
| `expect.rows.patch` | 该改动所在的公告版本号 | 用国服公告号，形如 `26.17`、`15.20`、`25.11` |
| `expect.rows.subject` | 同上，与 `expect.subject` 一致 | — |
| `expect.rows.ability` | 该改动的技能归属 | 只能填 `Q` / `W` / `E` / `R` / `被动` / `base`（`base` 表示"基础属性，不属于任何技能"） |
| `expect.rows.field_key` | 数值类别 | 只能从下面的清单里选一个 |
| `expect.rows.value` | 改动**之后**的数值片段 | 从公告里**原样摘抄**一段够独特的片段（8–30 字符），不要改写、不要翻译、不要加空格 |
| `why` | 一句话理由 | 说明「为什么这句话唯一指向这一条」 |

`field_key` 可选值（只能用这些）：

    damage（伤害）  cooldown（冷却）  cost（消耗/蓝耗）  crit（暴击相关）
    health（生命值）  health_regen（生命回复）  armor（护甲）  magic_resist（魔抗）
    resistances（双抗）  attack_damage（攻击力）  ability_power（法术强度/加成）
    attack_speed（攻速）  movement_speed（移速）  range（射程/范围）  shield（护盾）
    heal（治疗）  lifesteal（吸血）  tenacity（韧性）  slow（减速）  duration（持续时间）
    stacks（层数）  price（价格）  exp（经验）  ability_haste（技能急速）
    mana（法力值）  cast_time（施法时间）  magic_pen（法穿）  armor_pen（穿甲）
    max_rank（最大等级）  speed（速度）  stolen_stat（属性偷取）

## 二、这次要测什么（决定题目长什么样）

系统有两种工作方式：

- **不启用路由**：版本、对象、技能、字段能靠规则定下来的就定下来；定不下来的，
  检索会**把该对象的全部改动行都拿来排序**，字段只做"软偏好"（命中的排前面，但其余仍参与）。
- **启用路由**：先让模型判断"这句话问的是哪个技能、哪类数值"，再**只在该技能/该数值类别里检索**。

所以：**路由的价值 = 把正确那条从一堆候选里挑出来。**
如果一个问题不筛也能第一个命中，它**测不出任何差异**，不要出。
反过来，**"该对象在这个版本改动行很多、问法又只描述了技能而没点名"** 就是最有价值的题。

## 三、出题规则（最重要）

1. **必须唯一可判定**：一个懂游戏的人读完只能有**一个**合理解读。
   正例：「卡蜜尔那个盾改成多少」→ 该版本只有护盾一条，唯一。
   **反例**：「卡蜜尔改了什么」→ 指向不唯一，作废。
   **反例**：「卡西奥佩娅的技能伤害改过吗」→ 她 Q/E/R 都有伤害行，无法判定，作废。

2. **禁止点名技能，也禁止用技能名字**：
   - 不写 `Q`、`W`、`E`、`R`、`大招`、`被动`；
   - 不写官方技能名（如「圣银弩箭」「石化凝视」）；
   - 用**描述性说法**代替：如「那个盾」「位移技能」「减速的那个」「每段伤害」「强化后的伤害」
     「叠满之后的伤害」「外侧那一下」「那圈伤害」。
   - 若无法只用描述性说法做到唯一，就换对象或换版本，**不要**退回到点名技能。

3. **问法要口语化**：像玩家在群里问，而不是像文档。可以带「那个」「一下」「现在」
   「改成多少了」「是多少」这类口语成分。不要写成一个字段清单。

4. **数值必须来自官方公告**：`value` 必须是公告里的**新值原样**片段。
   不确定就换一条，**绝不猜测、绝不编造**。

5. **不要写"我不知道答案"的题**。每条必须能指出唯一正确的那一行。

6. **覆盖要分散**：至少覆盖 **12 个不同版本**，至少 **20 个不同英雄/装备**；
   同一对象最多出现 2 次；同一版本最多 4 条。

7. **版本号必须真实存在**。本次共 30 个版本可用：

       15.13 15.14 15.16 15.17 15.18 15.19 15.20 15.21 15.22 15.23 15.24
       25.10 25.11 25.15
       26.1 26.2 26.3 26.6 26.7 26.8 26.9 26.10 26.11 26.12 26.13 26.14 26.15 26.16 26.17 26.18

   其中 **25.11、15.20、15.23、26.1、26.3** 改动最多，最容易找到「同一对象多条改动行」的素材，
   建议优先去这几个版本翻。

8. **数量**：**40 条**（如果某些版本确实找不到合格的题，可以少到 35 条，
   但不得少于 35 条，也不要用不合格的题凑数）。

## 四、为什么这么苛刻（请务必理解再动笔）

这套题的目的不是"考系统答得对不对"，而是**区分两种工作方式**。
如果正确的那一行在"不筛技能"的情况下也排第 1，那么开不开路由都是对的，
这条题对结论毫无贡献；只有「正确行在混杂检索里排在后面、筛对技能后回到第 1」的题，
才能证明路由有用。

因此请优先挑这样的素材：

- 该对象在**该版本**有 **3 条以上**改动行（尤其是同一个技能下有多条，或不同技能都有伤害/加成）；
- 你写的问题能唯一指向其中一条；
- 玩家直觉上会问的就是那一条。

反过来说，**像"基础护甲改成多少"这种题请尽量少**——它太干净，测不出东西。

## 五、出题时禁止做的事（会导致整套题作废）

1. **禁止读本项目的语料或代码**：不要打开 `data/`、`docs/`、`tests/`、`*.json`（除了你要写的这个文件）。
   只能查**官方公告原文**与通用游戏资料。原因：一旦你参考了语料，出的题就会不自觉贴合系统的实现，
   那这套"盲测"就没有意义了。
2. **禁止在文件里写概率分布**：不要添加 `abilities`、`probabilities`、`confidence` 之类字段。
   你只能写"题目 + 正确答案"，**不能写"模型应该怎么答"**。
   历史教训：上一版案例集里写了我方预设的概率分布，结果测出来的"提升"是自证其说，
   换成真实模型后完全没有复现。
3. 不要出跨版本聚合题（「从 X 到 Y 改了几次」）、不要出无记录/越界题、不要出陷阱题
   （这些已有专门的案例集，本套只测单点数值）。
4. 不要出美术/皮肤/云顶/模式机制类问题。
5. 不要写英文或中英混排的问题（`Kai'Sa` 这类官方英文名不要出现在提问里）。

## 六、三条示范（照这个风格写，但不要照抄题目）

```json
{ "id": "e01", "kind": "routing_effect",
  "question": "26.18 卡蜜尔那个盾改成多少了",
  "expect": { "subject": "卡蜜尔",
    "rows": { "patch": "26.16", "subject": "卡蜜尔", "ability": "被动",
              "field_key": "shield", "value": "10 / 15 / 20 / 25%最大生命值" } },

  "question": "26.18 卡西奥佩娅那个技能伤害是多少",

## 七、交付前自检（请逐条核对并在最后报告结果）

1. 文件路径、JSON 语法、字段名是否完全符合第一节？
2. 每条是否都满足「唯一可判定」？把所有 `question` 连起来读一遍，逐条问自己
   "还有没有第二种合理解读"，有就删掉重写。
3. `ability` 字段是否只用了 `Q/W/E/R/被动/base`？是否**只出现在 `expect` 里**，
   而**没有出现在 `question` 里**？
4. `field_key` 是否都在允许清单内？
5. `value` 是否都能在官方公告里逐字找到？
6. 版本覆盖是否 ≥ 12 个、对象是否 ≥ 20 个、条数是否 ≥ 35？
7. 文件里是否**没有**任何概率/置信度字段？

## 八、最后请回答我三个问题

1. 你实际出了多少条？覆盖多少版本、多少对象？
2. 其中你认为**最有区分度**的 10 条是哪些（列 id），为什么？
3. 有哪些素材你本想用、但因为没有唯一解读而放弃了？各举 2 个例子。
`````

## 出完后怎么跑

```powershell
# 1. 确认文件在（出题方只能写这一个文件）
Test-Path tests\cases\routing_effect_cases.json

# 2. 真实模型跑对照（重复 3 次，抵消模型随机性）
python scripts\evaluate_routing.py --live --repeat 3 --cases tests\cases\routing_effect_cases.json --out "docs\Jev分层路由-效果集.md"

# 3. 报告会给出：off / shadow / active 三口径命中@1、改善与损害条数、
#    跳过语义决策的比例、每问调用与成本，以及跨轮翻转的案例
```

出完后告诉我，我会先做**出题质量体检**（唯一性抽检、value 是否真在公告里、是否有手写分布），
再跑对照并如实汇报——包括万一结论仍然是"没有提升"的情况。
