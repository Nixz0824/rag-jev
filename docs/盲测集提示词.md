# 盲测集生成提示词（交给 Codex）

> 用途：生成一份**答案级盲测集**，用来检验「RAG Jev」回答的真实准确率。
> 复制下面代码块里的全部内容作为给 Codex 的提示词。

---

```text
任务：为本地项目「RAG Jev」生成一份答案级盲测集（30–50 题），用于检验系统回答的真实准确率。
你只负责出题和给出标准答案，不要运行被测系统，也不要读被测系统的语料。

## 一、硬性禁止（违反即作废，先读完再动手）

1. 禁止打开、grep、参考以下任何文件（它们含被测语料或既有期望答案，看了就失去盲测意义）：
   - <项目根>\data\patch\knowledge.json
   - <项目根>\data\patch\raw\ 下的任何文件
   - <项目根>\tests\cases\eval_cases.json
   - <项目根>\tests\cases\trap_cases.json
   - <项目根>\tests\cases\parse_cases.json
   - <项目根>\docs\评测报告.md
   - <项目根>\docs\查询理解.md
2. 禁止运行 scripts\ingest_qq.py、scripts\evaluate_patch.py，禁止访问 http://127.0.0.1:18890。
3. 题目文本里不要写出答案，答案只写在 expect 字段里。
4. 不要凭记忆编造数值：每道题的答案必须能在官方公告页面上逐字找到，来源 URL 必须填在 source_url。
   查不到、拿不准的题就换一题。

## 二、唯一允许的资料来源

- 国服公告（首选）：https://lol.qq.com/news/index.shtml → 找到「26.XX版本更新公告」→ 点进正文
  （正文里数值形如「冷却时间：4 ⇒ 3.5」；注意有的公告标题是「X月X日X点停机版本更新公告」，正文里会写「发布26.XX版本」）
- 英文公告（国服页面打不开时备用）：https://www.leagueoflegends.com/en-us/news/game-updates/league-of-legends-patch-XX-XX-notes
- 版本范围：26.9 — 26.18，只出这个范围内的题；不要出更早或更新的版本。
- 只问召唤师峡谷的英雄与装备改动。
  不要问：皮肤、炫彩、云顶之弈、经典模式、海克斯大乱斗、斗魂竞技场、野区、大龙、地图机制、位置（打野/上单）、胜率、出装、英雄背景故事。

## 三、产出（严格要求格式）

写一个 UTF-8 的 JSON 文件到：
<项目根>\tests\cases\blind_cases.json

结构：
{
  "note": "出题说明：总题数、各 kind 数量、覆盖版本列表、你使用的来源（国服/英文）",
  "cases": [ 以下四种之一，每题严格只有 id/question/kind/expect/source_url 五个键 ]
}

1) 单点数值题，20 题，kind = "single"
{
  "id": "b01",
  "question": "26.17 亚索的暴击伤害改了吗",
  "kind": "single",
  "expect": {"patch": "26.17", "subject": "亚索", "field_key": "crit", "value": "-5%"},
  "source_url": "https://lol.qq.com/gicp/news/410/xxxxxxxx.html"
}
- field_key 只能从这里选：damage, cooldown, cost, crit, health, health_regen, mana, armor, magic_resist,
  resistances, attack_damage, ability_power, attack_speed, movement_speed, range, shield, heal, price,
  duration, stacks, max_rank, ability_haste, cast_time, magic_pen, armor_pen, slow, tenacity, lifesteal, exp, speed
- 可选键 ability，取值 "Q"/"W"/"E"/"R"/"被动"
- value 是公告里那条改动**新值**的连续子串，必须能在公告页面里逐字复制到（例如 "4 / 5.5 / 7 / 8.5 / 10%" 或 "2600"）

2) 改动汇总题，8 题，kind = "overview"
{
  "id": "o01",
  "question": "26.17 有哪些英雄被削弱",
  "kind": "overview",
  "expect": {"patch": "26.17", "subjects_any": ["内瑟斯", "格雷福斯", "薇恩"]},
  "source_url": "..."
}
- subjects_any：至少 2 个正确答案（系统答出其中之一即可），用官方中文名

3) 确实没有改动的题，5 题，kind = "absent"
{
  "id": "a01",
  "question": "26.16 希瓦娜改了什么",
  "kind": "absent",
  "expect": {"patch": "26.16", "subject": "希瓦娜"},
  "source_url": "第55行：该版本公告里确认没有这个对象的任何改动"
}
- 必须先确认：这个英雄/装备在该版本公告里**完全没有任何改动**

4) 应拒答题，5–8 题，kind = "out_of_scope"
{
  "id": "x01",
  "question": "26.17 出了哪些新皮肤",
  "kind": "out_of_scope",
  "expect": {},
  "source_url": "不属于公告数值范围"
}
- 可以问：皮肤/位置/胜率/其它服务器数值/不存在的版本（如 26.99）/版本内热修/攻略出装

## 四、题目风格（很重要）

- 用玩家真实会说的问法：混入口语与俗称（压缩、发条、ez、大虫子、刀妹、犽宿），允许错别字与省略。
- 其中约 30% 的题**不写版本号**（考察系统默认版本与追问行为）。
- 可以有 2–4 条中英混写，例如 "Yasuo Q 冷却现在几秒"。
- 每题只问一件事，不要一问多答；同一「版本 + 对象 + 字段」只能出现一次。
- 版本尽量分散：26.9 到 26.18 每个版本至少 3 题。

## 五、生成后自检（必须做，并把结果写进 note）

1. 每题的 value / subjects_any 都能在对应 source_url 页面上逐字找到；
2. 没有重复的（版本 + 对象 + 字段）组合；
3. note 里写清：总题数、各 kind 数量、覆盖的版本列表、来源是国服还是英文；
4. 用 python -c "import json;d=json.load(open(r'<项目根>\tests\cases\blind_cases.json',encoding='utf-8'));print(len(d['cases']))" 验证文件可解析，并把题数告诉我。
```

---

## 生成之后怎么跑

```powershell
python .\scripts\evaluate_patch.py --cases .\tests\cases\blind_cases.json --out .\docs\盲测报告.md
```

报告里会分开记账：

- **系统答错**：预期值在我们语料里存在，但系统没答对；
- **语料缺口**：预期值在我们语料里根本不存在（说明国服公告与英文公告数值不同，或我们的解析漏了）——这不算系统答错，但会单独列出来。

所以出题时如果只能拿到英文公告，也照做，缺口会被单独统计而不是算成失败。
